# Feedback

Папка для постоянных правил, которые появились после повторяющихся ошибок. Не сюда складываются разовые замечания и история сессий - для этого есть `retrospectives/`.

## Формат правила

```md
# Краткое название

## Rule

Что делать или чего не делать.

## Why

Почему это важно.

## How to apply

Как применять в будущих задачах.
```

## Уже выученные правила

- Не называть SyncDesk "helpdesk" без уточнения: продукт шире тикетов, но уже универсальной workflow-платформы.
- Не писать "enterprise-grade security" на раннем MVP.
- После архитектурного обсуждения всегда фиксировать: сейчас / позже / не делаем.
