# Principles

## Продукт

- MVP доказывает повторяемую боль, а не полноту платформы.
- Интеграции считаются ненадежными.
- Роли и audit log - часть ценности, а не бюрократия.
- Клиент должен понимать границы продукта.

## Код и архитектура

- Tenant boundary проверяется в каждом пользовательском сценарии.
- Idempotency для внешних событий обязательна.
- Secrets не логируются и не показываются повторно.
- Сначала observability для интеграций, потом новые коннекторы.

## Бизнес

- Не продавать custom integration как стандартный SaaS.
- Не обещать enterprise security до появления enterprise-пакета.
- Не добавлять тарифную сложность, если ее нельзя объяснить покупателю за минуту.

## Работа с Codex

Codex должен фиксировать trade-offs и не прятать риски в "потом разберемся".
