# План P2: необязательная полировка Codex Starter после v1

**Дата:** 2026-08-15
**Автор:** Арсений + Codex
**Приоритет:** P2 - оставить на потом
**Статус:** отложен
**Зависимости:** полностью завершённые [P0](../maintainer/history/plans/2026-08-15-starter-finalization-and-clean-handoff.md) и [P1](./2026-08-15-starter-p1-public-v1.md)

## Цель

После выпуска стабильной v1 улучшать удобство Starter только по подтверждённым проблемам реальных пользователей, не превращая его в большую обязательную систему.

## Результат простыми словами

P2 делает уже работающий Starter приятнее, но не меняет определение готовности.

Если P2 никогда не будет выполнен, v1 всё равно должна оставаться законченной и полезной.

## Почему это P2

Красивые сообщения, дополнительные интеграции и редкие сценарии не нужны для доказательства основной идеи. Если добавить их раньше, Starter станет сложнее ещё до того, как мы увидим реальные проблемы пользователей.

Поэтому P2 начинается только после использования v1 минимум на двух разных проектах.

## Что можно рассматривать после v1

- сокращение и улучшение текстов вопросов;
- более понятный показ прогресса интервью;
- более удобное объяснение найденных ошибок;
- улучшение восстановления после редких сбоев;
- дополнительные проверенные поверхности Codex и операционные системы;
- необязательные repo-skills;
- необязательные plugins, MCP, browser и automations;
- дополнительные примеры только для реально повторяющихся случаев;
- удобный путь обновления будущих версий Starter.

Ни один из этих пунктов заранее не считается обязательной функцией.

## Что запрещено делать в P2 без нового обоснования

- увеличивать обязательное интервью;
- добавлять папки на будущее;
- делать POST_AUTOPILOT обязательным;
- включать внешние сервисы по умолчанию;
- устанавливать skills, plugins или MCP без аудита и согласия;
- хранить один и тот же контекст в нескольких местах;
- возвращать удалённую служебную оболочку Starter в чистый проект;
- ослаблять гарантии безопасной очистки P0;
- блокировать работу проекта из-за необязательного расширения.

## Условия начала

P2 можно открыть только когда:

- [ ] P0 закрыт полностью.
- [ ] P1 закрыт полностью.
- [ ] Стабильная v1 использована минимум на двух разных проектах.
- [ ] Собраны конкретные повторяющиеся затруднения.
- [ ] Для каждого кандидата понятна польза.
- [ ] Известно, сколько нового контекста и сложности он добавит.
- [ ] Улучшение не решается простой правкой существующего текста.

## Фазы выполнения

### Фаза 0. Собрать доказательства

**Статус:** отложена

- [ ] Записать проблему словами пользователя.
- [ ] Указать, на каком шаге она возникла.
- [ ] Проверить, повторилась ли она на втором проекте или у второго пользователя.
- [ ] Отделить реальную проблему от личного предпочтения.
- [ ] Проверить, не решена ли проблема уже существующим механизмом.

**Проверка фазы:** у каждого кандидата есть минимум два независимых примера или один доказанный серьёзный риск.

**Результат фазы:** сформирован короткий список реальных проблем, а не список идей.

### Фаза 1. Отобрать улучшения

**Статус:** отложена

Для каждого кандидата проверить:

- [ ] Пользу для обычного пользователя.
- [ ] Расход контекста.
- [ ] Новую сложность и поддержку.
- [ ] Приватность и безопасность.
- [ ] Влияние на длительность онбординга.
- [ ] Работу минимум на двух разных проектах.
- [ ] Возможность оставить улучшение необязательным.

После проверки выбрать не больше трёх улучшений на один цикл.

**Проверка фазы:** отклонённые идеи не попадают в ядро и не создают новые папки.

**Результат фазы:** выбран маленький и обоснованный объём работы.

### Фаза 2. Создать отдельный план на каждое принятое улучшение

**Статус:** отложена

- [ ] Не реализовывать несколько несвязанных улучшений одним изменением.
- [ ] Для каждого принятого улучшения создать собственный план.
- [ ] Зафиксировать измеримый результат и границы.
- [ ] Сохранить обратную совместимость с чистым завершением P0.
- [ ] Добавить проверку, которая доказывает пользу и отсутствие регрессии.

**Проверка фазы:** один новый план соответствует одной функции и может быть принят независимо.

**Результат фазы:** P2 не превращается в бесконечное расширение Starter.

### Фаза 3. Повторно проверить минимальность

**Статус:** отложена

- [ ] Сравнить путь пользователя до и после улучшения.
- [ ] Убедиться, что базовый сценарий не стал длиннее без причины.
- [ ] Проверить `lite`, `standard` и `deep`.
- [ ] Проверить финальную очистку.
- [ ] Проверить новое окно.
- [ ] Удалить улучшение, если его польза не подтверждена.

**Проверка фазы:** v1 остаётся простой, а добавленное улучшение решает доказанную проблему.

**Результат фазы:** удобство выросло без раздувания ядра.

## Критерии готовности P2

- [ ] P0 и P1 не получили регрессий.
- [ ] Каждое реализованное улучшение подтверждено реальным использованием.
- [ ] Обязательный путь Starter не стал сложнее без измеримой пользы.
- [ ] Необязательные расширения остаются необязательными.
- [ ] Чистый проект после финализации не содержит новой служебной оболочки.

## Решение на текущий момент

P2 сейчас не начинать. Сначала нужен работающий P0, затем проверенная поставка P1, затем наблюдение за реальным использованием.
