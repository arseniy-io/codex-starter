# План P1: подготовка Codex Starter к передаче другим людям

**Дата:** 2026-08-15
**Автор:** Арсений + Codex
**Приоритет:** P1 - выполнять после P0
**Статус:** Фазы 0-4 завершены 2026-08-16; следующая - Фаза 5
**Зависимость:** [полностью завершённый P0](../maintainer/history/plans/2026-08-15-starter-finalization-and-clean-handoff.md)

## Цель

После готовности основного механизма сделать стабильную версию Starter, которую незнакомый человек сможет получить, запустить и пройти без помощи автора.

## Результат простыми словами

Другой человек должен суметь:

1. Получить свою копию Starter.
2. Открыть её в поддерживаемом Codex.
3. Увидеть короткую и точную инструкцию.
4. Написать `привет`.
5. Пройти Starter до чистого проекта.
6. Понять, какая версия у него установлена и где посмотреть ограничения.

## Почему это P1

P1 не исправляет главный механизм. Он превращает уже работающий Starter в понятную поставку для других людей.

Начинать P1 раньше нельзя. Хорошая упаковка не спасёт незаконченный или небезопасный процесс финализации.

## Что входит

- один понятный способ получить свою копию Starter;
- точная инструкция первого запуска без placeholder;
- документация поддерживаемых сред;
- честное описание приватности, hooks и ограничений;
- автоматические проверки основных сценариев;
- независимая приёмка новым пользователем;
- стабильный tag и GitHub Release;
- GitHub Template, если этот способ будет выбран.

## Что не входит

- изменение механизма завершения P0;
- обязательные plugins, MCP, browser или automations;
- новая большая архитектура;
- автоматический перенос пользовательского remote;
- необязательная визуальная полировка.

**Принятый контракт поставки:**

- основной путь - кнопка GitHub `Use this template` и создание нового репозитория в аккаунте самого пользователя;
- запасной путь - ZIP-архив конкретной стабильной версии, распакованный в новую папку;
- обычное клонирование исходного Starter не является пользовательским способом v1, потому что сохраняет `origin` на репозиторий Starter;
- Starter проверяет remote, но никогда сам его не меняет и не удаляет;
- если человек всё же открыл клон исходного Starter, процесс не продолжает опасный сценарий молча и требует явного решения пользователя;
- полностью поддерживаемая среда v1 - Codex desktop app на Windows в нативном режиме PowerShell и проект на файловой системе Windows;
- путь с кириллицей и работа с Git уже проверены; запасной ZIP-путь без Git допускается с явным предупреждением об отсутствии истории изменений;
- macOS, Linux, WSL, Codex CLI, IDE extension и cloud-задачи в v1 не объявляются проверенными, пока не пройдут отдельную живую приёмку.

GitHub подтверждает, что репозиторий из шаблона становится новым проектом с отдельной историей и одним начальным коммитом: [Creating a repository from a template](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template). ZIP даёт локальный снимок файлов без Git: [Downloading files from GitHub](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-files-from-github). Актуальная документация Codex подтверждает нативную работу Windows-приложения с PowerShell: [ChatGPT desktop app for Windows](https://developers.openai.com/codex/windows/windows-app).

**Проверка фазы:** основной и запасной пути создают отдельную копию без `origin` на исходный Starter. Текущий `origin` самого Starter проверен только для чтения и не изменялся. Фактический проход обоих способов остаётся частью Фазы 4.

**Результат фазы:** выбран основной путь через GitHub Template, безопасный запасной путь через ZIP и честная граница поддержки v1.

## Риски и защита

### Можно красиво упаковать сломанный механизм

Защита: P1 начинается только после полного закрытия P0.

### Пользователь может работать в исходном репозитории

Защита: отдельная копия, проверка remote и понятная инструкция без автоматических опасных действий.

### CI может создать ложное чувство готовности

Защита: автоматические проверки дополняются живой приёмкой в новых окнах.

### Публичные инструкции могут устареть

Защита: перед выпуском заново проверить актуальные возможности Codex и GitHub и указать границы версии.

## Порядок работы

1. Не начинать до полного закрытия P0.
2. Сначала выбрать способ поставки.
3. Затем сделать первый запуск и честную документацию.
4. После этого автоматизировать выпускные проверки.
5. Провести независимую приёмку на двух проектах.
6. Только затем готовить tag и release.
