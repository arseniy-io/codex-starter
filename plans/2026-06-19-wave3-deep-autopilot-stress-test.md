# План: волна 3 - тяжёлые проекты AUTOPILOT

Дата: 2026-06-19

## Цель

Проверить, как AUTOPILOT работает на тяжёлых проектах и включает ли `deep` только по настоящим deep-триггерам.

## Копии

- [x] `codex-starter-wave3-deep-01-b2b-saas`
- [x] `codex-starter-wave3-deep-02-marketplace`
- [x] `codex-starter-wave3-deep-03-ai-crm`

## Агенты

- [x] Агент 1: B2B SaaS для обработки заявок, технический фаундер, много требований, роли, данные, API, audit/export.
- [x] Агент 2: marketplace услуг, хаотичный основатель, много сторон сделки, платежи, доверие, споры.
- [x] Агент 3: AI CRM / AI-консультант для продаж, сложный AI-продукт, пользовательские данные, интеграции, trust/security.

## Режим запуска

Чтобы экономить токены, запускаем агентов по одному.

Сейчас запускается только агент 1. Остальные две копии создаются заранее и ждут отдельной команды.

## Что проверяем

- [x] AUTOPILOT выбрал `deep` по настоящим deep-триггерам для B2B SaaS.
- [x] `deep` дал risk/trust слой, но не превратился в бесконечную библиотеку.
- [x] `PROJECT_STATE.md` оставил короткий вход для нового окна.
- [x] `.business/INDEX.md` показывает, что читать по зонам риска и продуктового scope.
- [x] Агент не менял основной starter и писал отчёты только в своей копии.
- [x] Markdown-отчёты сохранены в UTF-8.

## Результат агента 1

Проект: B2B SaaS для обработки заявок и контроля операционной работы.

Оценка агента: 9/10.

Настоящие deep-триггеры:

- роли и права;
- клиентские данные;
- вложения;
- экспорт;
- API/webhooks;
- SLA;
- audit/security.

Главный вывод: `deep` здесь оправдан, но его нужно держать узко вокруг MVP, иначе он начнёт пухнуть.

## Результат агента 2

Проект: marketplace услуг.

Оценка агента: 9/10.

Настоящие deep-триггеры:

- две стороны сделки;
- платежи и выплаты;
- споры;
- отзывы;
- модерация;
- антифрод;
- trust/safety.

Главный вывод: `deep` нужен, потому что marketplace - это не каталог, а система доверия, денег и конфликтов.

## Результат агента 3

Проект: AI CRM / AI-консультант для продаж.

Оценка агента: 8.5/10.

Настоящие deep-триггеры:

- клиентские данные;
- роли и права;
- интеграции;
- audit trail;
- AI-рекомендации;
- explainability;
- privacy boundaries.

Главный вывод: `deep` нужен, но для AI-проектов особенно не хватает явного блока `MVP vs later` и deep-версии `PROJECT_STATE.md`.

## Итоговый вывод

Все три тяжёлых проекта получили `deep` по настоящим причинам.

Оставшаяся проблема: `deep` нужно сильнее защищать от распухания и дать ему отдельный короткий формат входа.

Подробный отчёт: `experiments/wave3-deep-projects-comparison.md`.
