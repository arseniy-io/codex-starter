# Дорожная карта: завершение и выпуск Codex Starter

**Дата:** 2026-08-15
**Автор:** Арсений + Codex
**Статус:** P0 завершён и принят 2026-08-16; в P1 завершены Фазы 0-4; P2 не начат

## Цель

Зафиксировать правильный порядок развития Starter: сначала безопасно закончить основной механизм, затем подготовить стабильную поставку для других людей и только после реального использования заниматься необязательной полировкой.

Этот файл является картой. Подробные действия, проверки и риски хранятся только в трёх связанных планах.

## Что делать сейчас

P0 закрыт автоматической и живой приёмкой. По отдельному направлению пользователя P1 начат, его Фазы 0-4 завершены:

[2026-08-15-starter-p1-public-v1.md](./2026-08-15-starter-p1-public-v1.md)

Следующей выполнять только Фазу 5 P1 - подготовку стабильного выпуска. Сначала собрать точный состав релиза и показать его пользователю. Commit, push, изменение remote, tag и release не выполнять без отдельного подтверждения.

## Условия перехода

### Из P0 в P1

Переход разрешён только когда:

- [x] полный путь `привет -> вопросы -> проверка -> очистка -> новое окно` работает;
- [x] ни один пользовательский или неизвестный файл не удаляется;
- [x] финальные документы относятся только к настоящему проекту;
- [x] новое окно не запускает Starter повторно;
- [x] все приёмочные сценарии P0 пройдены;
- [x] план P0 закрыт фактическим итогом и проверками.

### Из P1 в P2

Переход разрешён только когда:

- [ ] Starter получен и пройден независимым способом;
- [ ] два разных проекта завершили Starter без устных подсказок автора;
- [ ] автоматические и живые выпускные проверки пройдены;
- [ ] стабильная v1 выпущена после отдельного подтверждения;
- [ ] план P1 закрыт фактическим итогом и проверками.

### Начало отдельного улучшения P2

Переход разрешён только когда:

- [ ] проблема повторилась минимум в двух независимых случаях или создаёт один доказанный серьёзный риск;
- [ ] польза выше расхода контекста и новой сложности;
- [ ] улучшение не делает базовый путь длиннее без причины;
- [ ] на улучшение создан отдельный план одной функции.

## Как прежние приоритеты распределены теперь

### Перенесено в P0

- явный конец интервью;
- финальная проверка полного контекста;
- проверка реального статуса hooks и pre-commit;
- устранение противоречий в правилах;
- безопасная обработка `business/raw/`;
- передача работы между окнами через план и `PROJECT_STATE.md`;
- безопасное удаление оболочки Starter;
- проверка чистого проекта и нового окна.

Очистка раньше считалась P2 как вопрос удобства. После уточнения цели она стала P0: если Starter не удаляет свою служебную оболочку, он не считается завершённым.

### Перенесено в P1

- один рабочий способ получить собственную копию Starter;
- точная инструкция без placeholder;
- проверка поддерживаемых сред;
- автоматический выпускной контроль;
- условные правила происхождения методик и свежести метрик;
- независимая приёмка на двух проектах;
- стабильный tag и GitHub Release;
- GitHub Template, если он выбран основным способом поставки.

### Оставлено в P2

- улучшение формулировок и показа прогресса;
- дополнительные редкие сценарии;
- дополнительные поверхности и операционные системы после v1;
- необязательные skills, plugins, MCP, browser и automations;
- другие улучшения, подтверждённые реальным использованием.

## Общие ограничения

- Не начинать несколько приоритетов одновременно.
- Не переносить задачи P2 в ядро ради ощущения полноты.
- Не выполнять commit, push, изменение remote, tag или release без отдельного подтверждения.
- Не удалять неизвестные и пользовательские файлы.
- После каждой фазы обновлять соответствующий план фактическим результатом и проверками.
- Если меняется граница между P0, P1 и P2, сначала обновить эту карту и связанный план.

## Рекомендуемая последовательность

1. Утвердить эту карту и план P0.
2. Выполнить только Фазу 0 плана P0.
3. Показать точный контракт и манифест пользователю.
4. После подтверждения реализовать P0 по одной фазе.
5. Закрыть P0 живой приёмкой.
6. Перейти к P1 и подготовить стабильную поставку.
7. Выпустить v1 только после отдельного подтверждения.
8. Не начинать P2, пока нет данных двух реальных применений.
