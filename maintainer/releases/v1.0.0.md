# Codex Starter v1.0.0

**Статус:** локальный релиз-кандидат. Не опубликован.

## Коротко

Первая стабильная версия Codex Starter проводит пользователя от сообщения `привет` до обычного очищенного проекта. Интервью имеет три глубины, сохраняет прогресс между окнами, проверяет риски перед очисткой и не удаляет неизвестные файлы.

## Что проверено

- `lite` в отдельной Git-копии и `deep` в ZIP-подобной копии без Git;
- неровные и противоречивые ответы обычного пользователя;
- точный preview, отдельное подтверждение и безопасная очистка;
- сохранение пользовательских черновиков;
- пауза внутри интервью и продолжение с первого незавершённого вопроса;
- новое окно после очистки понимает проект и не запускает Starter повторно;
- единая выпускная проверка: lint, 30 тестов и publication/security audit.

## Известные ограничения

- Живая приёмка v1 выполнена только в приложении Codex на Windows, нативном PowerShell и на файловой системе Windows.
- macOS, Linux, WSL, Codex CLI, IDE extension и cloud-задачи пока не считаются проверенными.
- Project hook требует ручного доверия в новом окружении.
- Starter не создаёт Git, не меняет remote и не выполняет commit или push без отдельной команды.
- Пароли, токены, API-ключи и содержимое `.env` нельзя передавать в интервью.

## Предлагаемые настройки GitHub

Описание репозитория:

> Codex Starter - шаблон для безопасного онбординга проектов в Codex: AGENTS.md, режимы lite/standard/deep, бизнес-контекст, планы и проверяемая очистка.

Темы: `codex`, `project-template`, `onboarding`, `agents-md`, `ai-coding`.

Включить GitHub Template только после push проверенного релизного коммита.

## Внешние действия после подтверждения

1. Выполнить stage только по `maintainer/releases/v1.0.0-commit-allowlist.txt`, без `git add .`.
2. Создать commit с сообщением `release: Codex Starter v1.0.0`.
3. Отправить `main` в `origin` без изменения remote.
4. Дождаться успешного GitHub Actions на точном SHA.
5. Обновить описание и темы репозитория, включить GitHub Template.
6. Ещё раз проверить `/generate` и ZIP исходников.
7. Создать tag `v1.0.0` на проверенном SHA.
8. Создать GitHub Release `Codex Starter v1.0.0` с текстом из разделов выше.

Ни одно внешнее действие не выполняется без отдельной команды пользователя.
