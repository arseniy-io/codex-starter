# Smoke-test: обновлённая lite-ветка

Дата: 2026-06-19

## Что проверяли

Проверка после первой волны лёгких проектов: сможет ли обновлённый `lite` не раздувать маленький проект.

Тестовый сценарий: маленький локальный сайт, пользователь отвечает коротко и неидеально:

> «Ну нужен сайт, чтобы красиво было, цены, фотки, чтобы люди писали в WhatsApp. Пока не знаю точно.»

## Ожидаемый маршрут AUTOPILOT

1. Выбрать `lite`, а не `standard` или `deep`.
2. Задать максимум 5 вопросов.
3. Не проходить все блоки `company/products/audience/goals/economics/marketing/assets`.
4. Разложить мутный ответ на:
   - факт;
   - интерпретацию;
   - что уточнить позже.
5. Создать только короткий набор файлов:
   - `.business/INDEX.md`;
   - `.business/company/about.md`;
   - `.business/products/overview.md`;
   - `.business/audience/avatar.md`;
   - один файл по реальной задаче: например `.business/marketing/funnel.md` или `.business/assets/brand-guidelines.md`.
6. Не создавать `ai-clone/`, `mastery/`, `goals/`, `economics/`, `execution/`, risk/trust, роли, integrations или roadmap без прямой причины.
7. Создать `PROJECT_STATE.md` как короткий вход для нового окна.

## Результат проверки

Обновлённая инструкция теперь явно запрещает главную ошибку первой волны: маленький проект больше не должен проходить весь большой онбординг.

`lite` стал измеримым:

- до 5 вопросов;
- 3-5 бизнес-файлов;
- `AGENTS.md` -> `PROJECT_STATE.md` -> `.business/INDEX.md` -> 1-3 файла для нового окна;
- тяжёлые слои только по прямой причине.

## Остаточный риск

Риск остаётся не в структуре, а в дисциплине агента: если агент невнимательно прочитает AUTOPILOT, он всё ещё может начать создавать лишнее. Поэтому в средней волне нужно отдельно следить, не копируют ли агенты `lite`-ограничения туда, где уже нужен `standard`.

## Вывод

Smoke-test пройден на уровне инструкции. Обновлённый `lite` можно считать готовым к следующему проверочному прогону или к запуску средней волны.
