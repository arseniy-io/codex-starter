# Finding: изоляция тестовых агентов

Дата: 2026-06-19

## Что произошло

Во время первой и второй волн часть тестового контекста из копий попала в основной starter:

- `AGENTS.md` становился файлом тестового проекта;
- `PROJECT_STATE.md` становился состоянием тестового проекта;
- в корневые `experiments/` попадали агентские отчёты конкретной копии;
- в корневые `retrospectives/` попадали ретро конкретного тестового проекта;
- общий план волны иногда перезаписывался под одну копию.

## Почему это важно

Это не просто ошибка запуска. Это показывает реальный риск для AUTOPILOT:

если Codex работает с несколькими копиями или тестовыми проектами, ему нужны очень жёсткие границы источника истины.

Основной starter должен хранить только:

- общие планы волн;
- общие сравнительные отчёты;
- улучшения методологии;
- чистый `PROJECT_STATE.md` самого starter.

Тестовые проекты должны хранить свои `AGENTS.md`, `PROJECT_STATE.md`, `experiments/` и `retrospectives/` только внутри своих копий.

## Что исправлено

Основной `AGENTS.md` и `PROJECT_STATE.md` восстановлены под Codex Starter / AUTOPILOT.

Из корневого `experiments/` удалены агентские отчёты конкретных тестовых проектов.

Из корневого `retrospectives/` удалены ретро конкретных тестовых проектов.

Оставлены только общие отчёты:

- `experiments/wave1-light-projects-comparison.md`;
- `experiments/wave2-medium-projects-comparison.md`;
- другие общие baseline/review/scenario документы.

## Что нужно улучшить

Перед третьей волной добавить в рабочий промпт агентов и, возможно, в AUTOPILOT правило:

> Если работаешь в тестовой копии, все изменения, отчёты, планы и ретро создавай только внутри этой копии. Основной starter не является рабочей папкой тестового проекта и не должен изменяться агентом.

Также полезно требовать UTF-8 для всех Markdown-отчётов.

## Вывод

Изоляция агентов стала отдельным обязательным критерием качества. Без неё stress-test может портить основной starter и создавать ложные выводы.
