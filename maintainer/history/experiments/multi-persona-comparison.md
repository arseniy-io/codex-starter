## Главные выводы

- AUTOPILOT должен адаптировать глубину онбординга под размер проекта, а не вести всех по одной длинной схеме.
- Для маленьких проектов достаточно компактного `.business/` и одного рабочего плана. `ai-clone/` и `mastery/` должны включаться только по реальной причине.
- Для SaaS и проектов с данными нужны обязательные вопросы про роли, права, audit trail, интеграции, платежи, экспорт и чувствительность данных.
- Для личных экспертных проектов нужно явно разделять `.business/`, `ai-clone/` и `mastery/`: продукт, голос и метод не должны сливаться.
- Эксперименты полезны как отдельная зона, но не должны становиться постоянным контекстом, который Codex читает без причины.

## Решения для baseline

- Добавить в `AUTOPILOT.md` режимы глубины: `lite`, `standard`, `deep`.
- Добавить risk-based ветку для ролей, данных, интеграций, платежей, файлов, экспорта и security.
- Усилить `POST_AUTOPILOT.md`: личный контекст не заменяет бизнес-оффер.
- Усилить `templates/AGENTS.md.tmpl`, чтобы новые проекты сразу получали маршрутизацию, правила масштаба и security/context boundaries.
- Добавить в `QUALITY_CHECKLIST.md` проверку адаптивности starter.
