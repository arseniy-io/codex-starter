# План: волна 2 - средние проекты AUTOPILOT

Дата: 2026-06-19

## Цель

Проверить, как AUTOPILOT работает на проектах средней сложности и правильно ли выбирает `standard`.

Главная проверка: проект уже сложнее лендинга, поэтому `lite` недостаточен, но `deep` ещё не нужен без ролей, платежей, внешних API, пользовательских данных, файлов, экспорта или интеграций.

- [x] `codex-starter-wave2-medium-03-education`

## Агенты

- [x] Агент 1: онлайн-запись для студии, нормальный заказчик, ответы средние и местами сомневающиеся.
- [x] Агент 2: каталог услуг с админкой, бизнесовый заказчик, фокус на заявках, контроле и аналитике.
- [x] Агент 3: мини-образовательный продукт, эксперт с хаосом идей, много направлений и слабая структура.

## Что проверяли

- [x] AUTOPILOT выбрал `standard`, а не `lite`.
- [x] AUTOPILOT не ушёл в `deep` по названию режима.
- [x] `.business/` содержит больше структуры, чем маленький проект.
- [x] `PROJECT_STATE.md` даёт быстрый вход новому окну Codex.
- [x] В отчётах видно, какие файлы реально читались и какие оказались лишними.

## Итоговый вывод

`standard` выбран правильно во всех трёх проектах. После правки `lite` автопилот лучше отличает маленькие проекты от средних.

Главная новая проблема: верхняя граница `standard` пока мягкая. Агент может не назвать проект `deep`, но всё равно создать deep-like файлы: роли, security, integrations, roadmap, execution и расширенную экономику.

Дополнительный дефект stress-test: один из отчётов booking-копии записался с проблемной кодировкой. Нужно явно требовать UTF-8 для Markdown-отчётов.

Подробный отчёт: `experiments/wave2-medium-projects-comparison.md`.
