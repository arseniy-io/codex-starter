# Security By Design Check

## Что это

Легкая проверка продуктовой фичи через данные, роли, tenant isolation, audit log и edge cases.

## Когда применять

- Фича работает с пользовательскими данными, billing, ролями, интеграциями, файлами или экспортом.
- Меняется доступ пользователей.
- Добавляется внешнее API или webhook.

## Шаги

1. Назови данные, которые фича читает, пишет, экспортирует или удаляет.
2. Определи роли: кто может создать, увидеть, изменить, удалить.
3. Проверь tenant boundary: как исключается доступ к чужому tenant-у.
4. Определи, что попадает в audit log.
5. Опиши поведение при сбое внешней системы.
6. Проверь retention и удаление.
7. Сформулируй пользовательское ограничение рядом с опасным действием.

## Ограничения

Это не полноценный security audit. Метод нужен, чтобы не выпускать очевидно дырявые продуктовые решения на ранней стадии.
