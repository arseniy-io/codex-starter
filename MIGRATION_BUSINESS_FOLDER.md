# Migration: `.business/` -> `business/`

Этот файл нужен только тем, у кого проект уже был настроен по старой модели со скрытой папкой `.business/`.

Новая целевая модель starter:

- `business/` - видимая рабочая папка бизнес-контекста;
- `/business/` в `.gitignore` - реальные данные проекта по умолчанию приватные;
- `business/life-metrics.md` - карта живых цифр и источников свежих значений;
- `business/raw/` - исходники: транскрипции, переписки, выгрузки, заметки интервью;
- `AGENTS.md` - главный файл правил для Codex.

## Быстрый путь

1. Проверь, что у тебя нет незакоммиченных важных изменений:

```bash
git status --short
```

2. Переименуй папку:

```bash
git mv .business business
```

Если `.business/` не была tracked в git, используй обычное переименование в файловом менеджере или shell.

3. Проверь `.gitignore`. Для новой модели правило должно защищать корневую папку:

```gitignore
/business/
```

Так корневой приватный бизнес-контекст не попадёт в git, а учебные примеры внутри `examples/.../business/` смогут оставаться tracked.

4. Создай недостающие элементы, если их нет:

```text
business/life-metrics.md
business/raw/README.md
```

5. Замени старые ссылки в рабочих файлах:

```text
.business/INDEX.md -> business/INDEX.md
.business/...      -> business/...
```

Не переписывай исторические отчёты и старые ретроспективы только ради чистоты. Важно, чтобы текущие инструкции, шаблоны, prompts и `AGENTS.md` вели Codex в новую модель.

## Что делать с живыми цифрами

Если в старых файлах были цены, выручка, конверсии, количество клиентов или даты, не оставляй их как вечные факты.

В рабочем файле пиши:

```text
[Метрика]: LIVE -> business/life-metrics.md / "название метрики"
```

А в `business/life-metrics.md` укажи:

- что это за метрика;
- где брать свежее значение;
- как его получить;
- кто отвечает за источник.

## Что делать с raw-материалами

Большие транскрипции, переписки, выгрузки и интервью перенеси в `business/raw/`.

В обычных файлах `business/` оставляй короткие выводы и ссылки на нужный raw-источник. Не заставляй Codex читать весь `raw/` в начале задачи.

## Проверка

После миграции запусти:

```bash
python scripts/starter-lint.py
```

На Windows дополнительно:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/user-project-safety-check.ps1
```

Успешная миграция означает:

- в рабочих инструкциях больше нет старой основной модели `.business/`;
- `business/INDEX.md` ведёт к нужным файлам;
- `business/life-metrics.md` есть и используется для живых цифр;
- `business/raw/` существует, но не входит в обязательное стартовое чтение;
- корневая `/business/` защищена от случайного коммита.
