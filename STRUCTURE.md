# Repository structure

Короткая карта папок и файлов. Держи её как навигацию, а не как правила для Codex - правила живут в `AGENTS.md`.

| Путь | Роль | Почему нужен |
|---|---|---|
| `AGENTS.md` | Долговременные инструкции Codex | Чтобы агент работал одинаково в новых сессиях. |
| `PROJECT_STATE.md` | Короткий вход в текущее состояние | Чтобы новое окно Codex быстро понимало фокус, следующий шаг и какие файлы читать. |
| `AUTOPILOT.md` | Первый онбординг | Чтобы новичок прошёл настройку без ручного чтения всех файлов. |
| `autopilot/flows/` | Подробные сценарии первого онбординга | Чтобы `AUTOPILOT.md` оставался коротким, а Codex читал только выбранный flow: `lite`, `standard` или `deep`. |
| `autopilot/NEW_WINDOW_TEST.md` | Тест поведения Codex в новом окне | Чтобы проверять реальное поведение starter без гонки за оценкой. |
| `POST_AUTOPILOT.md` | Второй этап настройки | Чтобы добавить личный контекст, методологии и feedback loop после базового онбординга. |
| `business/` | Бизнес-контекст и второй мозг проекта | Чтобы Codex читал нужный контекст точечно и экономил окно; глубина зависит от масштаба проекта. |
| `business/life-metrics.md` | Живые метрики | Чтобы меняющиеся цифры брались из источника данных или инструкции получения, а не хардкодились в документах. |
| `business/raw/` | Сырые источники | Чтобы транскрипции, переписки и материалы лежали отдельно от обработанных выводов и не читались целиком без причины. |
| `business/execution/` | Операционное планирование | Чтобы недельные задачи не терялись между сессиями. |
| `ai-clone/` | Личный контекст автора | Чтобы Codex учитывал голос, стиль мышления и устойчивые правила пользователя. |
| `mastery/` | Авторские экспертные линзы и методы | Чтобы Codex применял методы конкретных авторов и практиков, а не общие роли. |
| `.codex/` | Project-level зона Codex | Чтобы config, onboarding state, hooks и guardrails были отделены от методологии. |
| `.codex/hooks.json` | Подключение Codex hooks | Чтобы policy-скрипт реально запускался как pre-tool-use guardrail. |
| `.codex/hooks/` | Детерминированные проверки | Чтобы опасные команды ловились скриптом, а не только текстовым правилом. |
| `.agents/skills/` | Локальные skills | Чтобы reusable workflows проекта не засоряли глобальную среду. |
| `.github/` | GitHub automation и issue templates | Чтобы публикация, CI и bug reports были стандартизированы. |
| `.vscode/` | Видимость рабочих папок | Чтобы `business/`, `.codex/`, `.agents/` были видны новичку. |
| `examples/` | Заполненные примеры | Чтобы было понятно, какого уровня детализации ждать. |
| `experiments/` | Текущие stress-tests и гипотезы | Чтобы запускать новые проверки starter, не смешивая временные выводы с постоянным контекстом. |
| `maintainer/` | История обслуживания starter-template | Чтобы старые планы, ретро и отчёты не загрязняли чистые рабочие папки пользовательского проекта. |
| `plans/` | Планы реализации | Чтобы каждая фича имела фазы, проверки и итог. |
| `prompts/` | Библиотека workflows | Чтобы не сочинять повторяемые промпты с нуля. |
| `retrospectives/` | Память после сессий | Чтобы следующий чат быстро понимал, что было сделано. |
| `scripts/` | Проверки шаблона | Чтобы ловить секреты и ошибки перед публикацией. |
| `templates/` | Заготовки генерируемых файлов | Чтобы AUTOPILOT создавал единообразный финальный проект. |
