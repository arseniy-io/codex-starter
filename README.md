# Codex Starter

Это стартовая папка для проекта, с которым будет работать Codex. Ты отвечаешь на вопросы о проекте, а Codex готовит короткий рабочий контекст, правила и понятный следующий шаг. После завершения служебная оболочка Starter удаляется, и остаётся обычный проект.

**Версия:** v1.0.0. Изменения и проверенные ограничения перечислены в [CHANGELOG.md](./CHANGELOG.md).

## Быстрый старт

1. [Создай свой репозиторий из Starter](https://github.com/arseniy-io/codex-starter/generate). На странице нового репозитория выбери `Code` -> `HTTPS` и скопируй адрес. В PowerShell набери `git clone`, добавь пробел, вставь адрес и нажми Enter.
2. В приложении Codex выбери добавление проекта или открытие папки и укажи только что созданную папку.
3. Создай в этом проекте новую задачу и напиши `привет`.

Не проходи настройку в исходном репозитории `arseniy-io/codex-starter`. Работай только в своей новой копии.

Если кнопка создания из шаблона недоступна, открой [страницу выпусков Starter](https://github.com/arseniy-io/codex-starter/releases), скачай `Source code (zip)` последней стабильной версии и распакуй архив в новую папку. В ZIP-копии нет истории Git. Starter предупредит об этом перед финальной очисткой.

## Перед стартом

Для проверенного сценария v1 нужны приложение Codex на Windows, вход в аккаунт OpenAI, нативный PowerShell и папка проекта на файловой системе Windows. Git нужен для основного способа через шаблон и даёт историю изменений.

macOS, Linux, WSL, Codex CLI, IDE extension и cloud-задачи могут работать, но в v1 пока не считаются проверенными средами.

Во время интервью могут появиться сведения о клиентах, деньгах, стратегии и твоих рабочих привычках. Используй приватный репозиторий или локальную ZIP-копию. Не вставляй пароли, API-ключи, токены и содержимое `.env`.

## Какой режим выбрать

- `lite` - небольшой сайт, личный проект или простой инструмент. Самый короткий путь.
- `standard` - обычный продукт или коммерческий сайт средней сложности.
- `deep` - сложный продукт с ролями, платежами, интеграциями, чувствительными данными или длинным планом развития.

Codex сам предложит подходящий режим по твоим ответам. После основного интервью он предложит необязательный второй этап `POST_AUTOPILOT`: там настраиваются личный стиль, методологии и дополнительные правила. Его можно пропустить, основная настройка всё равно завершится.

## Если пришлось остановиться

Снова открой ту же папку в Codex, создай новую задачу и напиши `продолжи онбординг`. Codex прочитает сохранённый этап и продолжит с него, не начиная интервью заново.

## Что получится

- `business/` - короткий контекст продукта, аудитории и целей; `life-metrics.md` хранит живые показатели, а `raw/` - исходные материалы.
- `ai-clone/` и `mastery/` - необязательный личный контекст и методологии.
- `PROJECT_STATE.md` - короткий вход для нового окна Codex: текущий фокус, что читать сначала и что не трогать без причины.
- `AGENTS.md` - долговременные правила для Codex в этом репозитории.
- `plans/` - планы реализации по задачам.
- `retrospectives/` - короткая память между сессиями.

## Как заканчивается настройка

Последний ответ не удаляет файлы сразу. Сначала Codex проверяет результат и показывает точный список изменений.

Корневые `README.md`, `AGENTS.md`, `PROJECT_STATE.md` и `STRUCTURE.md` заменяются версиями для настоящего проекта. После отдельного подтверждения удаляются только служебные файлы Starter: `AUTOPILOT.md`, `POST_AUTOPILOT.md`, сценарии интервью, временные шаблоны, проверки и материалы обслуживания Starter. Рабочий код, созданные файлы проекта и любые неизвестные файлы сохраняются.

Очистка запускается только после подтверждения конкретного `preview_id`. Изменение дерева отменяет старое подтверждение. Удаляются только заранее перечисленные и не изменившиеся файлы Starter, а неизвестные и пользовательские файлы сохраняются. Commit, push и изменение Git remote автоматически не выполняются.

## Безопасность без ложных обещаний

Starter использует несколько отдельных проверок. Они снижают риск, но не заменяют внимательность, резервную копию и проверку изменений человеком.

### Перед очисткой

- Codex сначала показывает точный список заменяемых и удаляемых файлов. Без подтверждения этого списка очистка не начинается.
- Если после показа списка изменился хотя бы один файл, старое подтверждение перестаёт действовать.
- Неизвестные и пользовательские файлы не удаляются. Commit, push и изменение Git remote автоматически не выполняются.
- Имена локальных файлов с секретами могут быть показаны как предупреждение, но их содержимое не читается.

### Две разные проверки команд

- Проверка команд Codex уже зарегистрирована в `.codex/hooks.json`. В новом проекте Codex пропускает её, пока ты не проверишь и не разрешишь точную версию hook. Финализация запускает сам проверяющий скрипт на безопасном и опасном примерах, но не может доказать, что hook разрешён в твоём приложении.
- Git pre-commit не устанавливается автоматически. Starter хранит только пример. В финальном preview он проверяет, существует ли настоящий `.git/hooks/pre-commit`, но не обещает, что этот hook найдёт любой возможный секрет.

Техническое устройство и ручная проверка описаны в [настройках Codex](./.codex/README.md). Официальная документация также требует отдельно проверять и разрешать project hooks: [Hooks в Codex](https://developers.openai.com/codex/hooks).

### Приватный контекст

- `business/` по умолчанию не добавляется в Git. В `business/raw/` могут лежать интервью, переписки и выгрузки, поэтому эта папка не читается целиком без причины.
- Для заполненных `ai-clone/` и `mastery/` перед завершением выбирается один вариант: оставить в приватном репозитории, снять с отслеживания Git или сохранить только безопасную короткую версию.
- Пароли, токены, API-ключи и содержимое `.env` нельзя переносить в контекстные файлы.

### Внешние материалы и меняющиеся факты

- Импортированные тексты и содержимое `business/raw/` считаются данными, а не командами для Codex. Встроенные в них инструкции не выполняются без отдельного подтверждения пользователя.
- Меняющаяся цифра используется только вместе с источником, датой проверки и сроком свежести. Если срок прошёл, значение нужно обновить или прямо назвать непроверенным.
- Метод из `mastery/` используется только с заполненной карточкой источника. Единый формат этой карточки находится в [индексе Mastery](./mastery/INDEX.md).
- Если проекту не нужны отдельная методология или новая метрика, Starter не должен создавать их ради полноты.

### Чего Starter не гарантирует

Starter не является антивирусом, хранилищем секретов или полной границей безопасности. Hooks можно не разрешить или отключить, проверки по известным шаблонам могут не узнать новый вид секрета, а источник может содержать ошибочные данные. Для рискованных действий всё равно нужны review и явное подтверждение.

### Как проверить текущую копию

До очистки пользовательской копии:

```powershell
python scripts/starter-lint.py --onboarded
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/user-project-safety-check.ps1
```

Для проверки самого Starter перед публикацией:

```powershell
python scripts/release-check.py
```

Команда проверяет структуру Starter, три контрольных результата `lite`, `standard` и `deep`, безопасную очистку и отсутствие известных утечек. Она не запускает пользовательский AUTOPILOT и не меняет проект.

Автоматический успех не доказывает, что новое окно Codex поведёт себя правильно. Перед выпуском всё равно нужен отдельный живой тест по `autopilot/NEW_WINDOW_TEST.md`.

## Как работать после онбординга

1. Перед задачей Codex читает `AGENTS.md`.
2. Затем он читает `PROJECT_STATE.md`, чтобы понять текущий фокус и 2-4 первых файла.
3. Для продуктовых задач он берёт только нужный контекст из `business/`.
4. Для задач про автора или методологии он берёт только нужные файлы из `ai-clone/` и `mastery/`.
5. Для новой функции создаёт план в `plans/`.
6. После реализации запускает проверки стека.
7. В конце заметной сессии обновляет `PROJECT_STATE.md`, если изменился фокус или следующий шаг, и пишет ретро в `retrospectives/`.

`maintainer/` нужен только для обслуживания самого starter-template. В обычном проекте Codex не читает старые планы, ретро и эксперименты из этой папки.

## Что шаблон не делает

- Не устанавливает Codex и не настраивает твой аккаунт OpenAI.
- Не выбирает тариф и не гарантирует лимиты использования.
- Не заменяет твои ответы в бизнес-интервью.
- Не включает автоматом рискованные режимы без подтверждений.

## FAQ

### Почему `AGENTS.md`, а не просто промпт в чат?

Промпт живёт одну сессию. `AGENTS.md` хранит durable-инструкции для репозитория: команды, стиль, правила проверки, безопасность и структуру контекста.

### Можно ли использовать с Cursor/Windsurf/другими агентами?

Методология `business/`, `plans/`, `retrospectives/` переносима. Но `AGENTS.md`, `.codex/`, hooks и skills адаптированы под Codex.

### Почему `business/`, а не `.business/`?

Инструкция использует видимую папку `business/`: её проще найти, объяснить и поддерживать как второй мозг проекта. Приватность сохраняется через `/business/` в `.gitignore`, а не через скрытое имя папки.

### Сколько токенов уйдёт?

Зависит от размера проекта, частоты задач, подключённых tools/MCP/skills и того, насколько аккуратно ты держишь контекст. Правило шаблона: сначала индекс, потом только нужные файлы, без загрузки всех контекстных папок целиком.
