# Сравнение: волна 1 - лёгкие проекты

Дата: 2026-06-19

## Что проверяли

Три маленьких проекта с тремя разными стилями общения:

- лендинг мастера маникюра;
- сайт локального ремонта холодильников;
- мини-портфолио фотографа.

Цель проверки: понять, не раздувает ли AUTOPILOT маленькие проекты и может ли новое окно Codex быстро войти в работу через `AGENTS.md` + `PROJECT_STATE.md`.

## Результаты по проектам

### 1. Маникюрный лендинг

Оценка агента: 8/10.

Что сработало:

- `lite`-режим подошёл;
- проект остался маленьким;
- новое окно Codex может быстро понять проект через `AGENTS.md`, `PROJECT_STATE.md` и `.business/INDEX.md`;
- короткие и неполные ответы пользователя не сломали автопилот.

Что мешало:

- для совсем маленького лендинга шагов всё ещё многовато;
- starter ощущается как система шире, чем нужно одному лендингу;
- часть вопросов можно свернуть в один короткий блок.

### 2. Ремонт холодильников

Оценка агента: 7/10.

Что сработало:

- автопилот быстро свёл проект к заявкам, телефону, районам, цене "от" и срочному вызову;
- `PROJECT_STATE.md` дал хороший короткий вход;
- бизнес-контекст можно держать в 4-5 файлах.

Что мешало:

- `ai-clone/` и `mastery/` выглядят тяжёлыми для маленького локального сайта;
- стартовая структура тянет к более крупному продукту;
- нужен более явный минимальный набор для локальных сервисов.

### 3. Портфолио фотографа

Оценка агента: 7/10.

Что сработало:

- `lite`-режим помог не раздувать контекст;
- автопилот смог превратить эмоциональные и туманные ответы в рабочий проектный контекст;
- для нового окна достаточно короткой цепочки чтения.

Что мешало:

- творческому проекту не нужен SaaS-обвес;
- часть вопросов звучит слишком бизнесово;
- автопилоту не хватает отдельного способа превращать настроение, вкус и стиль в конкретные решения.

## Общий вывод волны

`PROJECT_STATE.md` подтвердил ценность. Это главный выигрыш: новое окно Codex может быстро понять маленький проект без чтения всей `.business/`.

Но `lite`-режим пока не 10/10. Он работает, но его приходится сознательно сжимать. Для маленьких проектов автопилот должен сам жёстче отсекать лишнее.

## Что стало ясно

- Маленькому проекту обычно хватает `AGENTS.md`, `PROJECT_STATE.md`, `.business/INDEX.md` и 3-5 коротких файлов.
- `ai-clone/` нужен только если задача реально про голос, стиль или личные предпочтения.
- `mastery/` нужен только если пользователь просит методологию, discovery или экспертный разбор.
- `plans/` и `retrospectives/` для маленького проекта нужны осторожно: план полезен для stress-test, но для обычного микролендинга может быть лишним.
- `experiments/` полезен для проверки автопилота, но не должен быть частью ежедневного чтения проекта.

## Рекомендация перед средней волной

Перед запуском средней волны стоит слегка улучшить AUTOPILOT:

1. Добавить более явный `lite-mini` маршрут для совсем маленьких проектов.
2. Ограничить маленький проект 3-5 бизнес-файлами по умолчанию.
3. Явно сказать: `ai-clone/` и `mastery/` не заполнять в lite, если нет прямой причины.
4. Добавить короткий сценарий для творческого человека: переводить вкус, настроение и референсы в конкретные решения.

## Текущая оценка AUTOPILOT после волны 1

Для маленьких проектов: 7.3/10 по агентам.

Моя оценка: 8/10.

Почему выше среднего агентов: основа правильная и `PROJECT_STATE.md` реально решает главную боль с новым контекстным окном.

Почему не выше: `lite`-ветку ещё нужно сделать проще, короче и увереннее.
