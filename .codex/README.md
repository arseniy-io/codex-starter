# Codex project settings

Эта папка хранит project-level настройки Codex для репозитория.

## Что здесь лежит

- `config.toml` - минимальный project config без рискованных переопределений.
- `hooks.json` - project hook registration для Codex.
- `hooks/pre_tool_use_policy.py` - локальная проверка команд и tool input на опасные паттерны.

## Почему так

Codex использует `AGENTS.md` для durable-инструкций, `.codex/config.toml` для project config и hooks для детерминированных проверок вокруг tool calls. Настройки сделаны консервативно: они не меняют sandbox, approval mode или модель пользователя.

## Как работает hook

Hook подключён через `.codex/hooks.json` к `PreToolUse` для shell-команд. Скрипт читает JSON из stdin, ищет опасные команды и возвращает `hookSpecificOutput.permissionDecision: "deny"` при срабатывании или `"allow"` для безопасного smoke-test примера.

Команда hook резолвит корень репозитория через `git rev-parse --show-toplevel`, поэтому не зависит от того, из какой подпапки Codex запустил shell-команду. Windows-команда явно декодирует путь как UTF-8, чтобы не ломаться в папках с кириллицей.

Codex загружает project-local hook только для доверенного слоя `.codex/`. Перед первым запуском команды нужно отдельно проверить и разрешить точную версию hook. Если определение изменилось, Codex помечает его для повторной проверки и до подтверждения пропускает.

Финализация напрямую запускает policy-скрипт на двух примерах и проверяет ответы `deny` и `allow`. Это подтверждает работу скрипта, но не подтверждает, что hook разрешён и реально подключён в текущем приложении Codex.

Git pre-commit - другая защита. Пример лежит в `.github/hooks/`, но Starter не устанавливает его автоматически. Финальный preview сообщает только о наличии настоящего файла `.git/hooks/pre-commit`.

Понятное описание всех гарантий и ограничений находится в разделе `Безопасность без ложных обещаний` корневого `README.md`.

Если схема hooks изменилась, сверяйся с официальной документацией Codex:
