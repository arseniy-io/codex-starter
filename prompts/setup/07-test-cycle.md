# Проверка рабочего цикла

**Когда брать:** после создания `AGENTS.md`, `business/`, `plans/`, `retrospectives/`. До начала реальной работы над проектом.
**Что делает:** проверяет, что Codex понимает цикл `plan → implement → verify → retro` без создания учебного мусора в корне проекта.
**Результат:** уверенность, что Codex будет создавать планы и ретро только под реальные задачи.

## Промпт

```prompt
Проверь рабочий цикл проекта без создания учебных файлов.

Действуй так:

1. Прочитай `AGENTS.md`.
2. Прочитай `business/INDEX.md`, но не загружай всю `business/`.
3. Объясни, когда для задачи про выручку, цены, клиентов, конверсии или даты нужно читать `business/life-metrics.md`.
4. Покажи, когда для реальной задачи нужно создать план в `plans/`.
5. Покажи, какие проверки нужно запускать после реализации.
6. Покажи, когда нужно создать ретро в `retrospectives/`.
7. Назови 2-3 примера задач, где план и ретро нужны, и 2-3 микрозадачи, где достаточно краткого итога в ответе.

Не создавай `HELLO.md`, hello-план или hello-ретро. Если нужна живая демонстрация, предложи сделать её в `examples/hello-cycle/`, а не в корне проекта.
```

## Проверка

После выполнения вручную проверь, что Codex:

- объяснил цикл `plan → implement → verify → retro`;
- не создал учебные файлы в корне проекта;
- не предложил читать все контекстные папки целиком;
- объяснил правило `business/life-metrics.md` для живых цифр;
- различил заметную задачу и микрозадачу.

Если Codex не смог объяснить цикл или предложил создать учебный мусор в корне проекта - значит `AGENTS.md` написан плохо. Попроси Codex доработать и повтори проверку.

## Важно

Эта проверка не должна засорять проект. Первые реальные план и ретро должны появиться только после настоящей задачи или заметной сессии.
