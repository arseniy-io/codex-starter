# Playwright MCP - Codex управляет браузером

**Когда брать:** когда у тебя уже есть работающий сайт (локально или в сети) и ты хочешь, чтобы Codex мог его тестировать сам.
**Что делает:** подключает Playwright MCP - Codex открывает настоящий браузер, тыкает на кнопки, заполняет формы, делает скриншоты, проверяет мобильную вёрстку.
**Результат:** подключённый браузерный инструмент или понятный план подключения через актуальный MCP/config твоей поверхности Codex.

## Зачем

- Сделал лендинг - Codex сам открывает его, проверяет формы, шлёт скриншоты с ошибками.
- Надо протестировать чужой сайт - Codex прогоняет сценарий и пишет отчёт.
- Регрессия после правки - автоматический прогон, чтобы убедиться что ничего не сломал.

⚠️ **Совет:** у некоторых Playwright работает нестабильно. Если у тебя полезут странности - не зависай, поставь альтернативу (Chrome DevTools MCP) и иди дальше.

## Установка

```prompt
Установи Playwright MCP в мой текущий проект Codex.

1. Найди актуальный официальный способ подключения Playwright MCP или другого браузерного инструмента для моей поверхности Codex.
2. Проведи аудит безопасности - это браузер с полным доступом, важно понять что он делает.
3. Если безопасно - установи локально для этого проекта по актуальной схеме Codex/MCP. Не придумывай формат config без проверки.
4. После установки покажи как его вызывать, какие команды доступны (navigate, click, screenshot, fill и т.д.).
5. Сделай проверочный прогон на безопасной тестовой странице или моём локальном сайте, если он уже запущен.
```

## Твой первый автотест

Когда у тебя появится сайт:

```prompt
Используй Playwright MCP. Открой мой локальный сайт по адресу http://localhost:3000.

1. Сделай скриншот первого экрана.
2. Прокрути страницу вниз до конца - скриншот каждого блока.
3. Найди главную форму (кнопка «Купить» / «Оставить заявку»), заполни тестовыми данными (имя: Тест, email: test@example.com), нажми кнопку.
4. Что произошло после отправки? Скриншот результата.
5. Переключи viewport на мобилку (iPhone 14). Повтори прогон.
6. Собери отчёт: что работает, где баги, какие блоки выглядят плохо на мобилке.
```

Codex пойдёт и всё сделает. Получишь тестовый отчёт со скриншотами - и ни строчки кода сам не написал.

## Важно про токены

Каждый подключённый MCP/tool может добавлять инструкции, схемы и контекст к работе агента. Не подключай десятки MCP «на всякий случай» - держи только те, которыми активно пользуешься.
