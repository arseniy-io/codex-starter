# Генерация AGENTS.md под твой проект

**Когда брать:** после заполнения `business/` через интервью.
**Что делает:** создаёт `AGENTS.md` в корне проекта - главный файл с правилами работы, который Codex читает первым перед каждым действием.
**Результат:** компактный `AGENTS.md` под твой стек и тип проекта.

## Зачем

`business/` - это **знания** (зачем делаем проект). `business/life-metrics.md` - это способ получать свежие цифры. `AGENTS.md` - это **правила** (как Codex работает со знаниями). Без `AGENTS.md` Codex каждый раз «придумывает» подход заново. С ним - следует единому методу.

⚠️ Держи файл коротким: только устойчивые правила, команды, проверки и контекстные маршруты. Всё редкое вынеси в prompts или docs.

## Промпт

```prompt
Создай в корне проекта файл AGENTS.md. Основа - шаблон в templates/AGENTS.md.tmpl.

Действуй так:

1. Прочитай templates/AGENTS.md.tmpl - это заготовка с плейсхолдерами.
2. Прочитай `business/INDEX.md`, затем только те файлы внутри `business/`, которые нужны для заполнения плейсхолдеров.
3. Заполни все плейсхолдеры в шаблоне ({{PROJECT_NAME}}, {{PROJECT_ONE_LINER}}, {{STACK}}, {{LANGUAGE_RULE}}) на основе моих ответов из business/.
4. Проверь, что в AGENTS.md осталось правило: для метрик, выручки, цен, клиентов, конверсий и дат сначала читать `business/life-metrics.md`.
5. Если каких-то данных не хватает - задай мне уточняющие вопросы ПО ОДНОМУ с 3-4 вариантами ответа.
6. Запиши итоговый файл в корень проекта как AGENTS.md.
7. Проверь что файл компактный. Если раздулся - сократи воду и детали, которые лучше вынести в prompts. НЕ удаляй разделы про план для каждой функции и про рефлексию.
8. Покажи мне итоговый файл и спроси что доработать.

Важно: два правила должны остаться в AGENTS.md обязательно:
- «План для каждой новой функции в plans/»
- «Ретроспектива в конце каждой сессии в retrospectives/»
- «Динамические цифры только через business/life-metrics.md и LIVE»

Всегда отвечай на русском.
```

## Проверка

После создания попроси Codex объяснить, как он будет действовать для первой реальной задачи:

1. Какие файлы он прочитает сначала.
2. Когда создаст план в `plans/`.
3. Какие проверки запустит.
4. Когда создаст ретро в `retrospectives/`.
5. Как не будет читать все контекстные папки целиком.

Если Codex предлагает читать всё подряд или создавать учебные файлы в корне проекта - значит `AGENTS.md` написан плохо. Попроси доработать и повтори проверку.
