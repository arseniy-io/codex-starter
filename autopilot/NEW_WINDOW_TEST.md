# New Window Test

Короткая проверка реального поведения Starter без памяти прошлого окна. Используй её только в тестовой копии проекта. Основной Starter и пользовательские файлы не очищай ради теста.

## Что считается успехом

До финализации новое окно продолжает с сохранённого этапа. После успешной очистки оно видит обычный рабочий проект, не запускает онбординг и предлагает перейти к первой настоящей задаче.

## 1. Чистый старт

Открой новое окно и напиши `привет`.

Ожидаемое поведение: Codex читает `AGENTS.md`, состояние онбординга и предлагает начать настройку. Он не читает целиком `business/`, `ai-clone/`, `mastery/`, все планы и ретро.

## 2. Аудит без онбординга

Открой новое окно и напиши: `Оцени AUTOPILOT и скажи, что улучшить. Файлы не меняй.`

Ожидаемое поведение: Codex не запускает интервью, читает только нужные файлы, ничего не меняет и не коммитит.

## 3. Три режима

В отдельных тестовых копиях проверь маленький проект, обычный продукт и сложный проект с ролями, платежами, данными, API или AI.

Ожидается соответственно `lite`, `standard` и `deep`. Codex читает только общий flow и один выбранный flow, задаёт его точные вопросы и не создаёт лишнюю библиотеку контекста.

## 4. Продолжение после прерывания

Сначала ответь на один вопрос внутри незавершённого шага и дождись следующего вопроса. Проверь, что подтверждённый смысл уже появился в `business/raw/onboarding-notes.md`, а state содержит ближайший точный подшаг. Закрой окно и открой новое.

Ожидаемое поведение: Codex читает state и заметки, не повторяет записанный вопрос и начинает с первого действительно незавершённого вопроса.

Затем отдельно закрой окно после окончания интервью, но до очистки, и открой новое.

Ожидаемое поведение: Codex видит `finalization.current_stage`, не повторяет вопросы и продолжает с последней безопасной стадии. Для проверки технической точки можно запустить:

```powershell
python autopilot/finalization/finalize.py --root . status
```

## 5. Preview и подтверждение

Создай в тестовой копии один неизвестный пользовательский файл. Запусти preview.

Ожидаемое поведение:

- рабочие документы ещё не заменены, файлы не удалены;
- неизвестный файл показан как сохраняемый;
- изменённый известный файл Starter останавливает очистку;
- пользователь видит точный `preview_id`;
- без явного подтверждения `apply` не запускается;
- изменение дерева делает старый preview недействительным.

## 6. Чистое новое окно

Только в отдельной тестовой копии подтверди preview и заверши очистку. Проверь, что AUTOPILOT, POST_AUTOPILOT, состояние и служебные папки Starter исчезли, а неизвестный файл сохранился.

Открой новое окно и напиши: `Что это за проект и что делать дальше?`

Ожидаемое поведение: Codex использует короткий маршрут `AGENTS.md` -> `PROJECT_STATE.md` -> индекс нужной зоны -> 1-3 файла. Он не упоминает Starter и не предлагает повторный онбординг.
