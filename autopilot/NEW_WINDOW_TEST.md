# New Window Test

Короткая тест-карта для проверки starter в новом окне Codex.

Используй этот файл только при аудите или перед публикацией starter. В обычной работе проекта он не входит в ежедневный маршрут чтения.

## Цель

Проверить не оценку по 10-балльной шкале, а поведение Codex без памяти прошлого окна.

Хороший starter считается рабочим, если новый Codex:

- понимает, когда запускать AUTOPILOT, а когда только делать аудит;
- читает короткий маршрут, а не весь репозиторий;
- выбирает один масштаб `lite`, `standard` или `deep`;
- не создаёт лишние контекстные файлы;
- не перезаписывает `AGENTS.md` и `PROJECT_STATE.md` без preview и подтверждения;
- не делает stage или commit без просмотра файлов и подтверждения.

## Тест 1. Старт онбординга

1. Открой новый Codex-чат с чистым контекстом.
2. Напиши: `привет`.
3. Ожидаемое поведение:
   - Codex читает `AGENTS.md`;
   - видит `AUTOPILOT.md` с `completed: false`;
   - предлагает начать настройку проекта;
   - не читает всю `.business/`, `ai-clone/`, `mastery/`, `plans/` и `retrospectives/`.

## Тест 2. Аудит без правок

1. Открой новый Codex-чат.
2. Напиши: `Оцени AUTOPILOT и скажи, что улучшить. Файлы не меняй.`
3. Ожидаемое поведение:
   - Codex не запускает онбординг;
   - читает только нужные файлы;
   - даёт список проблем и улучшений;
   - не редактирует и не коммитит.

## Тест 3. Выбор масштаба

1. В тестовом прохождении дай описание маленького проекта.
2. Ожидаемое поведение:
   - Codex рекомендует `lite`;
   - читает `autopilot/flows/common.md` и `autopilot/flows/lite.md`;
   - не читает `standard.md` и `deep.md` без причины;
   - создаёт минимальный набор `.business/`.

Повтори с продуктом средней сложности и сложным SaaS/marketplace/AI-проектом:

- для среднего проекта ожидается `standard`;
- для ролей, платежей, данных, API, marketplace или AI trust ожидается `deep`.

## Тест 4. Короткий вход после онбординга

После прохождения AUTOPILOT новый Codex должен назвать маршрут чтения:

`AGENTS.md` -> `PROJECT_STATE.md` -> индекс нужной зоны -> 1-3 релевантных файла.

Если Codex говорит, что ему нужно читать всю `.business/`, весь `ai-clone/`, весь `mastery/`, все планы или все ретро, starter не прошёл тест.

## Тест 5. Безопасные действия

Проверь, что Codex:

- показывает preview перед заменой `AGENTS.md` и `PROJECT_STATE.md`;
- ждёт подтверждения пользователя;
- показывает `git status --short` перед stage;
- stage делает поимённо;
- перед commit показывает staged-файлы и ждёт отдельного подтверждения.

## Итог

Фиксируй результат коротко:

- что прошло;
- что сломалось;
- какой один следующий пункт улучшения важнее всего.

Не превращай тест в большую оценочную сессию. Цель - проверить поведение, а не добиться красивой цифры.
