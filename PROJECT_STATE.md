# PROJECT_STATE

## Проект

**Codex Starter / AUTOPILOT** - стартовая методология для проектов разной сложности, чтобы Codex быстро понимал проект в новом контекстном окне и не тратил лишние токены на чтение всей папки.

## Текущий фокус

Проверить AUTOPILOT волнами на разных размерах проектов и довести его до максимально удобного состояния для ежедневной работы Codex.

Сейчас текущая версия starter дорабатывается после stress-test на лёгких, средних и тяжёлых проектах.

## Читать сначала

- `AGENTS.md` - правила работы в репозитории.
- `PROJECT_STATE.md` - короткий вход в текущий статус.
- `AUTOPILOT.md` - первая часть настройки проекта.
- `POST_AUTOPILOT.md` - вторая часть настройки и lifecycle.
- `QUALITY_CHECKLIST.md` - финальная проверка качества starter.

## Ключевые файлы проекта

- `AUTOPILOT.md` - первая часть автопилота и режимы прохождения.
- `autopilot/flows/` - подробные сценарии шага 8: общий формат, `lite`, `standard`, `deep`.
- `POST_AUTOPILOT.md` - вторая часть и lifecycle слоёв после онбординга.
- `templates/PROJECT_STATE.md.tmpl` - шаблон короткого входа для нового окна.
- `templates/AGENTS.md.tmpl` - шаблон правил работы Codex.

## Читать по задаче

- `.business/INDEX.md` - если задача про продукт, аудиторию, UX, ценность или бизнес-контекст.
- `ai-clone/INDEX.md` - если задача про голос, стиль, личные предпочтения или устойчивые ошибки.
- `mastery/INDEX.md` - если задача про методологию, discovery или экспертный подход.
- `experiments/README.md` - если задача про stress-test, гипотезы или результаты прогонов.
- `autopilot/NEW_WINDOW_TEST.md` - если задача про проверку поведения Codex в новом окне перед публикацией starter.

## Не читать без причины

- всю `.business/`;
- весь `ai-clone/`;
- весь `mastery/`;
- все планы и ретро;
- тестовые копии на рабочем столе как источник истины.

## Следующий шаг

Перед публикацией проверить чистоту starter: корневая `.business/` не должна содержать тестовый проект, `PROJECT_STATE.md` должен оставаться коротким входом, а test-runs и experiments не должны быть ежедневным маршрутом чтения.

## Когда обновлять этот файл

Обновляй `PROJECT_STATE.md`, только если изменился текущий фокус, следующий шаг или список ключевых файлов. Не превращай этот файл в дневник работы.
